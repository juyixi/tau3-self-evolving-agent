# 代码生命周期与归档规范

本文档是项目所有实施阶段必须遵守的核心工程规范。阶段计划中的测试 gate、review checkpoint 和完成状态均继承本文规则。

## 目录职责

### `src/`

只保存 rollout、memory、OPD 训练、模型调用和正式评测在运行时直接依赖的代码。只供测试、阶段验收、人工迁移或故障排查使用的实现不得进入 `src/`，也不得由生产包公开导出。

### `scripts/`

只保存用户长期执行的产品级工作流入口，例如 baseline、fast loop、OPD 训练、迭代编排和正式评测。一次性 smoke、环境诊断、数据迁移和 review 辅助命令不得进入 `scripts/`。

### `tools/`

保存部署前检查、环境诊断、数据迁移和人工排障等长期运维工具。工具可以调用稳定的核心接口，但核心运行代码不得反向导入 `tools/`。工具不是训练或评测数据流的一部分。

### `tests/`

保存持续保护当前有效契约的自动化测试，以及对应 fixtures、fakes、stubs 和测试支持实现。测试辅助实现统一放在 `tests/support/` 或紧邻测试模块，不得放入 `src/`。

### `docs/archive/`

只保存压缩后的里程碑、迁移结论和仍有审计价值的历史决策。不得复制原始 review diff、临时 brief、执行报告、终端日志或 `.superpowers/` 内容。

## 阶段结束审计

每个阶段标记完成前必须执行：

1. 列出该阶段新增、修改和删除的文件。
2. 使用代码搜索区分生产引用、测试引用和无引用文件。
3. 将仅被测试引用的实现移到 `tests/`。
4. 将仍有长期诊断价值的非产品命令移到 `tools/`。
5. 删除已被正式工作流取代且没有独立运维价值的文件。
6. 将需要长期保留的历史结论压缩为一个里程碑摘要。
7. 更新所有命令、导入和文档引用。
8. 运行默认测试、当前阶段集成门禁、`git diff --check` 和旧路径残留检查。
9. 在阶段提交中记录保留、迁移和删除清单。

生命周期审计未通过时，阶段不得标记完成，也不得开始下一阶段的核心实现。

## 保留、迁移与删除判定

满足任一条件时保留在核心目录：

- 后续阶段的运行时数据流会直接调用它。
- 删除后会破坏当前公开运行契约或可复现性契约。
- 它封装了真实的领域边界，而不是单纯转发另一个构造函数。

满足以下条件时迁移：

- 只被自动化测试引用：迁入 `tests/`。
- 只用于部署、诊断或迁移但仍会重复使用：迁入 `tools/`。
- 只剩历史审计价值：压缩后迁入 `docs/archive/`。

满足以下条件时删除：

- 只为一次阶段验收或 review 服务，且目的已经完成。
- 没有生产引用，且不保护独立的长期契约。
- 只是无行为包装、重复入口或已被新命令取代的兼容层。

Git 已跟踪文件由 Git 历史承担原始归档；被 Git 忽略的本地 scratch 文件不属于项目交付。

## 测试与验收门禁

- 目录迁移必须先让测试指向新路径并观察预期失败，再迁移实现恢复通过。
- 删除测试辅助生产代码前，必须在 `tests/support/` 建立等价测试能力。
- 删除无行为包装层时，应删除只验证该包装层存在的测试，不得把它改写成重复断言以维持测试数量。
- 默认测试不得依赖网络、真实 API 凭证、GPU、大模型权重或 Tau2 checkout。
- 真实 Tau2、用户模拟器和 Qwen endpoint 检查使用显式集成门禁。
- 每个阶段必须搜索旧模块路径、旧命令和被删除符号，结果必须为空或仅存在于迁移历史说明中。

## 禁止事项

- 禁止在 `src/` 中保留 fake、mock、scripted policy 或测试数据生成器。
- 禁止让核心运行代码依赖 `tools/`、`docs/archive/` 或 `.superpowers/`。
- 禁止为了保持旧路径而保留没有已发布兼容承诺的转发模块。
- 禁止把完整 review diff、代理报告和调试日志提交为项目文档。
- 禁止以“后续可能会用”为理由保留没有明确调用方和职责的抽象层。
